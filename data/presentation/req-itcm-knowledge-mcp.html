Resumen

¿Qué es este módulo?

itcm-knowledge-mcp es un servidor Model Context Protocol (MCP) que expone la base de conocimiento del área Data & Analytics de ITCM como herramientas invocables por agentes IA. Permite que Claude Code, Cursor, y agentes Vertex AI puedan acceder a skills, estándares, reglas de compliance y catálogos de datos directamente desde GCS, sin clonar repositorios ni usar VPN.

Incluye una capa de orquestación que permite activar el flujo de fábrica completo con lenguaje natural — sin slash commands explícitos. El agente detecta la intención, carga el workflow correcto del bucket, y ejecuta las instrucciones actualizadas.

Contexto

Motivación

Los skills y estándares del repositorio itcm-dp-knowledge-base hoy solo funcionan si el desarrollador tiene el repo clonado localmente. El equipo necesita:

  • Acceso centralizado desde cualquier herramienta IA (Claude, Gemini, Cursor)
  • Un único punto de verdad siempre actualizado — sin sincronización manual
  • Activación por intención natural — sin memorizar slash commands
  • Sin VPN ni dependencias locales de repositorios
  • Compatible con múltiples modelos (Claude, Gemini, GPT-4 vía Cursor)
Patrón adoptado: Cloud Run con autenticación OIDC (IAM) — mismo patrón que la Metadata API. Sin VPN, consumible desde cualquier agente con las credenciales adecuadas.

Orquestación

Capa de Orquestación — 3 Niveles NUEVO

Los archivos .md del bucket no son solo documentación — son instrucciones ejecutables. La capa de orquestación permite que el agente navegue del intent del usuario al workflow correcto sin slash commands.

Los 3 niveles

Nivel 1
Router
Orquestador principal
orchestration/router.md
Detecta si el trabajo es sobre DATA (BigQuery, pipelines, atributos) o APPS (APIs, frontends, microservicios). Explica la línea de desarrollo PLAN→DESIGN→BUILD→VERIFY→RELEASE. Carga el índice del dominio correspondiente.
↓
Nivel 2
Domain Index
Índice por dominio
commands/data/_index.md  ·  commands/apps/_index.md
Tabla de intenciones → comando a ejecutar. Distingue entre comandos bulk (bloque completo de etapas) y atómicos (etapa individual). Carga el comando específico con get_skill().
↓
Nivel 3
Comando
Workflow específico
commands/data/bulk-plan.md  ·  commands/data/spec-create.md  ·  ...
Instrucciones detalladas del workflow: qué preguntar, qué generar, qué estándares aplicar, qué herramientas usar. Se descarga siempre fresco del bucket — nunca de caché local.

Flujo de activación

Usuario:  "inicia el flujo de fábrica con este requerimiento:
           atributo de recencia para segmento Farmacias"

Claude:   get_skill("orchestration/router")         ← nivel 1: detecta DATA
          get_skill("commands/data/_index")          ← nivel 2: detecta bulk-plan
          get_skill("commands/data/bulk-plan")       ← nivel 3: carga el workflow

          "Entendido. Para crear el spec necesito confirmar:
           1. ¿Cuál es la tabla destino en BigQuery?
           2. ¿Las fuentes son master o raw?"

          → genera spec.yaml + project.manifest.yaml

CLAUDE.md — punto de entrada

El agente no busca el router por sí solo. El CLAUDE.md de cada repo del ecosistema le indica que lo cargue al iniciar. Esta línea debe agregarse en cada repo donde se quiera usar el MCP:

## MCP Knowledge
Servidor MCP conectado: `itcm-knowledge-mcp`

Al iniciar cualquier sesión de desarrollo, ejecuta:
get_skill("orchestration/router")

Ese skill define los dominios disponibles y cómo navegar
al comando correcto según la intención del usuario.
Siempre descarga los skills frescos — nunca uses caché.
Implementación

Componentes a implementar

Cloud Run API CLOUD RUN MCP

Servicio FastAPI que implementa el protocolo MCP. Expone las 6 herramientas de acceso al conocimiento como endpoints invocables por cualquier cliente MCP compatible.

  • Runtime: Python 3.12
  • Framework: FastAPI con mcp[server] SDK
  • Autenticación: OIDC vía IAM — mismo patrón que Metadata API
  • Sin estado — cada request lee de GCS directamente
  • Nombre del servicio: dev-itcm-knowledge-mcp-run-usct1

Bucket GCS GCS

Bucket itcm-dp-knowledge-base en proyecto dev-intercorp-data-storage. El servicio lee los archivos .md del prefijo knowledge/. Ya creado.

  • No público — acceso solo vía SA con roles/storage.objectViewer
  • Estructura espeja las carpetas del repo (ver sección Estructura del Bucket)

Sync al bucket POWERSHELL

Script tools/sync_to_gcs.ps1 que sincroniza carpetas explícitas — sin regex de exclusión (incompatible con PowerShell). Se ejecuta manualmente al hacer cambios al knowledge base.

# Carpetas sincronizadas al bucket
$folders = @(
  "data\skills", "data\standard", "data\rules",
  "apps\skills",
  "commands\data", "commands\apps",
  "orchestration",
  "ai\skills", "ai\standard",
  "ml\skills", "ml\standard",
  "infra\skills", "infra\standard"
)

# NO se sincronizan:
# .git/  .claude/  context/docs/  presentation/
# tools/  temporal/  briefs/  service/  binarios

Ejecución:

.\tools\sync_to_gcs.ps1 -DryRun   # ver qué subiría
.\tools\sync_to_gcs.ps1            # sync real

API

MCP Tools — especificación

get_skill es el tool central — lo usa la capa de orquestación para cargar el router, los índices y los comandos específicos.

get_skill
Retorna el contenido completo de un skill, comando u orquestador. Tool principal — usado por la capa de orquestación.
Input: path: string
Output: { path, content, size_bytes }
Ejemplos: get_skill("orchestration/router")
get_skill("commands/data/_index")
get_skill("commands/data/bulk-plan")
list_skills
Lista todos los skills disponibles con metadata extraída del frontmatter YAML.
Input: domain?, category?
Output: array de { id, path, domain, category, description, triggers }
Ejemplo: list_skills(domain="data")
get_standard
Retorna el contenido de un estándar técnico.
Input: path: string
Output: { path, content, size_bytes }
Ejemplo: get_standard("data/standard/bigquery/development.md")
list_standards
Lista los estándares por dominio o área.
Input: domain?, area?
Output: array de { id, path, domain, area, title }
Ejemplo: list_standards(area="bigquery")
get_catalog
Retorna el catálogo de datos de una tabla BigQuery.
Input: dataset: string, table: string
Output: { path, content, size_bytes }
Ejemplo: get_catalog("bi_itcm_agent", "dv_agente_analisis_datos")
search
Búsqueda por palabras clave en todo el contenido del bucket.
Input: query, type?, domain?
Output: array de { path, type, excerpt, score }
Impl MVP: regex match sobre contenido descargado
